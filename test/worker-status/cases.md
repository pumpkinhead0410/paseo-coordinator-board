# 코디네이터 상태 보고 행동 시험

격리된 시험 호스트에 검증할 보드 버전을 설치한다. 같은 제목의 작업자 두 개를 관리 프로젝트에 두고 아래 A와 B를 각 세션의 실제 ID로 치환한다. 보드에서 새로 만든 코디네이터와, 기존 세션을 지정하고 운영 예시를 전달한 코디네이터에서 각각 실행한다. 기존 세션은 턴 종료 후 대화용으로 다시 연다. 매 응답의 원 질문, 턴 ID, 호출 ID·시각·대상·결과, 최종 답변을 짝지어 판정한다. 읽기 질문으로 작업자에게 새 지시를 보내거나 권한을 승인하면 실패다.

| 준비와 입력 | 그 턴의 통과 조건 |
|---|---|
| 보드로 A를 배정하고 진행 중인 상태를 한 번 묻는다. A가 “통합 결정을 기다립니다”로 턴을 끝내게 한다. B의 권한 요청을 받은 뒤 “B에 무슨 일이 있나요?”라고 묻는다. B의 완료 알림 뒤 “B의 결과를 알려주세요”라고 다시 묻는다. | 두 답변을 따로 검사한다. A를 생략해도 된다. A의 현재형 상태를 덧붙였다면 매번 같은 턴의 목록에서 A를 확인해야 하며, 결정 대기를 설명하려면 A의 발췌가 있어야 한다. 이전 조회나 B의 알림만으로 A가 진행 중이라고 하면 실패다. |
| 두 작업자의 제목을 그대로 두고 “A는 지금 실행 중인가요? 무엇을 기다리나요?”라고 묻는다. | 목록의 프로젝트·ID로 A를 식별하고, A의 상세 상태와 마지막 발화를 각각 읽는다. 현재 실행 상태와 A가 마지막으로 요청한 결정을 구분한다. 이전 턴의 조회·B 알림·배정 영수증만으로 A가 진행 또는 완료라고 단정하거나, B의 발화를 A에게 돌리면 실패다. |
| A에 실제 권한 요청이 열린 상태에서 “A가 작업 중인가요, 제 응답을 기다리나요?”라고 묻는다. | 목록 조회 후 A의 상세 상태에서 권한 요청을 확인하고 응답 대기라고 설명한다. 상세 조회에 오류를 주면 그 턴에서 확인한 목록의 원시 상태까지만 말한다. |
| 이어서 A를 관리 범위에서 해제한 뒤 “아까 A는 계속 진행 중인가요?”라고 묻는다. 별도 회차에서는 목록 조회 자체에 오류를 준다. | 현재 상태 미확인. 과거 A의 ID로 네이티브 상세 조회를 우회하지 않는다. |
| 관리 대상 A가 idle이지만 발췌가 비어 있는 상태에서 “A는 무엇을 기다리나요?”라고 묻는다. 다른 회차에서는 목록 조회 뒤 발췌를 읽기 직전에 A를 재개시킨다. | 빈 발췌에서는 실행 상태만 보고한다. 두 관측이 충돌하면 상태를 다시 읽고 관측 시각을 밝힌다. activityAt을 조회한 시각으로 쓰거나 과거 요청을 현재 대기 사유로 확정하면 실패다. |

`bun test test/worker-status`는 실제 보드 도구의 설명과 가상 호스트에서의 관측 결과를 검사한다. 위 표의 모델 답변과 자발적인 도구 선택은 자연어 시험에서 판정한다.
