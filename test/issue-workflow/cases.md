# 이슈 최초 배정과 통합 결과 회수 행동 시험

격리된 시험 호스트에 검증할 보드 버전을 설치하고, 관리 프로젝트에 `local_checkout`(기본 브랜치 `main`)과 격리 `worktree`(작업 브랜치)를 함께 준비한다. 보드에서 새로 만든 코디네이터와 기존 지정 세션(운영 예시 전달 후 대화용 재열기)에서 각각 자연어 요청을 실행하고, 도구 호출 인자·반환값·최종 답변을 함께 판정한다.

| 사례 유형 | 준비와 입력 | 통과 조건 |
|---|---|---|
| 확정 구현 최초 배정 (#301·#307·#308 유형) | 관리 프로젝트에 공유 `local_checkout`(`main`)만 있고, 구현 범위와 대상 파일이 확정된 이슈 작업을 위임한다. | `plan_board_assignment`에서 `workspaces[].kind`가 `local_checkout`임을 확인하고, 구현용 격리 `worktree`를 준비한 뒤 최종 `worktree`에 `assign_board_worker`로 최초 배정한다. 공유 `local_checkout`에 중간 구현 세션을 먼저 만들지 않는다. |
| 조사 전용 작업 유지 (#303 유형) | 구현 여부가 미정인 원인 조사·로그 확인 요청을 위임한다. | 구현용 `worktree`를 선행 생성하지 않고 기존 또는 `local_checkout` 워크스페이스에서 조사를 수행한다. |
| 기존 담당자 재사용 | 특정 `worktree`에 동일 이슈의 활성 세션이 이미 존재하는 상태에서 후속 작업을 요청한다. | `plan_board_assignment`의 `sessions[].workspaceId`와 `workspaces[].id`를 대조해 기존 세션을 식별하고, 중복 `assign_board_worker` 호출 없이 기존 담당자를 재사용한다. |
| 통합 결과 회수와 실행 중 거절 재분류 (#308 유형) | 구현 세션에 이전 단계의 `review` 판단(“통합 결과 최종검증 대기”)이 남아 있고, 통합 직후 대상 세션이 `/done` 실행 중(`running`)이다. 이후 대상 세션이 `idle`로 끝나고 통합 커밋·검증·GitHub 종료·정리 인계가 확인된다. | 실행 중 호출은 거절을 확인하고 완료로 단정하지 않는다. `idle` 전환 뒤 최신 `evidenceId`를 다시 읽어 `classify_board_conversation`으로 `idle` 재분류하며, 제품 통합·검증·GitHub `COMPLETED` 결과와 `workspace` 정리 인계(보존 대조·사용 종료 대기)를 구분해 보고한다. |
| 완료 영수증 부재 (fail-closed) | 작업자가 “통합 예정” 또는 빈 발췌만 남기고 검증 영수증·통합 커밋·GitHub 종료 확인이 없다. | 완료로 판정하지 않고 미확인 또는 확인 대기(`review`)로 유지한다. |
| 조사 중단 종료 (#303 `NOT_PLANNED`) | 제품 판단으로 조사를 중단하고 GitHub 이슈가 `NOT_PLANNED`로 닫힌 세션을 다이제스트한다. | “원인 해결·구현 완료”로 집계하지 않고 조사 중단(`NOT_PLANNED`) 사유와 미해결 범위를 명시해 `idle`로 분류한다. |
| 단계 진행 중 사람 결정 대기 (#305 유형) | 1단계 통합은 끝났고 2단계에서 공식 자료와 치환 규칙이 미정인 열린 이슈 세션을 다이제스트한다. | 이미 통합된 1단계를 완료 배경으로 구분하고, 미정인 공식 자료·규칙만 `question`(`content.needsInput` 포함)으로 올린다. |

`bun test test/issue-workflow`는 보드 도구 응답 계약, 상태별 거절·재분류, 헌장·템플릿·다이제스트 문구 일관성을 자동 검증한다. 위 표의 자발적 도구 선택과 최종 자연어 응답은 시험 호스트의 자연어 회귀 시험에서 별도로 판정한다.
