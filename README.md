# 세션별 코디네이터 보드

Paseo에서 여러 프로젝트를 운영할 때, 내가 결정할 일과 각 세션의 진행 상황을 한 화면에서 봅니다. **내 결정** 카드에서 작업 세션에 답하거나, 여러 작업의 순서를 조정해 달라고 코디네이터에 요청할 수 있습니다.

## 설치하고 첫 카드 보기

세션을 실행할 컴퓨터에 **Paseo 0.16.2 이상**이 필요합니다. 앱에서 **Settings → Plugins**를 열고 **Enable plugins**를 켜세요. **Plugin source**에 아래 설치 ID를 붙여 넣고 **Install plugin**을 누르세요. [공식 플러그인 페이지](https://paseo.sh/plugins/devbrother2024/coordinator-board)

```text
devbrother2024/coordinator-board
```

터미널에서 설치하려면 같은 컴퓨터에서 다음 명령을 실행하세요.

```sh
paseo plugin install devbrother2024/coordinator-board
paseo plugin ls coordinator-board
```

상태가 `running`이면 사이드바에서 **세션별 코디네이터 보드**를 열고 관리할 프로젝트를 선택하세요. 기존 세션은 **프로젝트별 진행**에 나타납니다. **추천 설정으로 시작**을 눌러 코디네이터를 만든 뒤 **다이제스트 요청**을 누르면 답변이 필요한 항목을 확인할 수 있습니다.

레지스트리로 설치한 보드의 새 버전을 확인하려면 `paseo plugin update coordinator-board --check`를 실행하세요. 업데이트하려면 `paseo plugin update coordinator-board`를 실행하고 제안된 변경을 확인합니다.

**Git·ZIP 설치**도 가능합니다. Git이 있는 호스트에서는 `paseo plugin install git:devbrother2024/paseo-coordinator-board --ref main`으로 기본 브랜치를 설치합니다. 이 문서의 버전을 설치하려면 `main` 자리에 `v0.5.24`를 넣으세요. 전체 커밋 SHA도 사용할 수 있습니다. ZIP은 압축을 푼 뒤 `paseo-plugin.json`이 있는 폴더에서 `paseo plugin install .`을 실행하고 그 폴더를 보관하세요. [Paseo 플러그인 안내](https://paseo.sh/docs/plugins)

**세션 진행 → 진행 중 모아보기**에서 선택한 프로젝트의 실행 중인 세션을 최근 활동순으로 확인하고 열 수 있습니다. 각 행에는 프로젝트와 실행 호스트가 표시됩니다. **프로젝트별**을 선택하면 칸반으로 돌아갑니다. 마지막으로 선택한 보기는 기기별로 저장됩니다.

**내 결정**에서는 기한이 지났거나 지금 처리해야 하는 카드가 맨 위에 옵니다. 그다음은 답변이나 권한 승인을 기다리는 작업이고, 나머지 카드는 오늘, 이번 주, 그 이후에 기한이 있는 작업, 기한 없는 작업 순으로 표시합니다. 같은 순위에서는 대기를 시작한 시각이 확인된 오래된 카드부터 표시합니다. 처음에는 다섯 장이 보입니다. 답변을 쓰거나 병합을 확인하는 동안에는 갱신이 와도 해당 카드의 자리를 유지합니다.

질문과 설명에서는 원래 줄바꿈과 마크다운을 볼 수 있습니다. 목록의 각 항목은 줄을 나누고, 코드나 경로는 고정폭 글꼴로 표시합니다.

데스크톱과 웹에서는 요청, 답장, 추가 질문의 입력창에서 **⌘+Enter**(Mac) 또는 **Ctrl+Enter**(Windows·Linux)로 전송할 수 있습니다. **Enter**는 줄을 바꿉니다. 전송 버튼에 마우스를 올리거나 Tab 키로 버튼을 선택하면 이 기기의 단축키가 표시됩니다.

**내 결정**에서 답장을 보내거나 PR을 병합하면 방금 누른 자리에 카드 제목과 처리 결과가 남습니다. 답장을 보낸 뒤에는 접힌 카드의 **받은 세션 열기**를 눌러 답장이 도착한 대화를 바로 확인할 수 있습니다. 확인을 마치면 **숨기기**를 누르세요. 나중에 확인하려면 목록 아래의 **최근 결정 기록**을 여세요. 답장에는 보낸 문구와 시각이 표시됩니다. 받은 세션과 원래 질문을 올린 세션을 구분해 확인할 수 있습니다. 보드에만 저장한 답에서도 원래 세션을 찾을 수 있습니다. 프로젝트 칸반의 **결정 후속**에도 같은 기록이 남습니다. 기기 로그인처럼 프로젝트에 속하지 않는 요청은 **공통**에 표시됩니다. 받은 세션의 후속 응답이 확인되면 카드에 표시되며 세션 칩에서 대화 전문을 열 수 있습니다.

## 첫 화면과 관리 범위

1. Paseo 사이드바에서 **세션별 코디네이터 보드**를 엽니다. 제목 아래 호스트 이름을 확인하고 **다이제스트에서 관리할 프로젝트 선택**에서 원하는 프로젝트를 추가합니다. 보드는 열린 동안 30초마다 갱신됩니다.
2. 관리 대상을 바꾸려면 **설정 → 보드에서 관리할 프로젝트 선택**을 엽니다. 세션이 아직 없는 프로젝트도 선택할 수 있습니다.
3. 다른 프로젝트의 작업 세션 하나만 포함하려면 **설정 → 다른 프로젝트의 세션 하나 연결**을 엽니다. 이름이나 ID로 검색한 뒤 원래 프로젝트와 워크스페이스를 확인합니다. 이미 관리 중인 대상 프로젝트를 선택하고 **이 프로젝트에 연결**을 누릅니다.
4. 연결한 세션은 대상 다이제스트와 칸반에 한 번 표시됩니다. 대화, 작업 파일, 세션 ID는 원래 워크스페이스에 남습니다. **프로젝트 연결 해제**를 누르면 원래 프로젝트도 관리 중일 때는 그 프로젝트에 다시 표시됩니다. 원래 프로젝트가 관리 범위 밖이면 보드에서 사라집니다.

**설정 → 보드 언어**에서 **한국어** 또는 **English**를 선택할 수 있습니다. 언어는 이 기기에 저장되고, 세션에서 읽은 질문과 직접 쓴 답은 원문으로 표시됩니다. [English overview](OVERVIEW.md)

## 코디네이터에 첫 작업 맡기기

1. 다이제스트에 넣을 프로젝트를 고른 뒤 **추천 설정으로 시작**을 누릅니다. 기본 헌장을 가진 코디네이터 세션이 전용 워크스페이스에 생깁니다. 같은 요청을 다시 누르면 기존 세션을 재사용합니다. 이미 사용하던 세션은 **설정 → 기존 세션에서 코디네이터 지정**에서 연결합니다. 자동 생성할 때는 호스트에서 코디네이터 역할을 지원하는 실행기를 고릅니다. 사용할 실행기가 없으면 기존 MCP 지원 세션을 지정할 수 있습니다.
2. **코디네이터에게 맡길 일**에 “편집 프로젝트의 자막 검수 결과를 정리해 줘”처럼 입력하고 **코디네이터에 요청 보내기**를 누릅니다. 지정한 세션이 관리 중인 프로젝트와 워크스페이스, 기존 작업, 사용 가능한 모델을 확인한 뒤 작업자를 배정합니다. 작업 위치가 모호하면 코디네이터가 확인하도록 헌장에서 안내합니다. **코디네이터 세션 열기**에서 답을 읽습니다. **다이제스트 요청**을 누르면 그 세션에 현재 내 결정을 정리해 달라는 요청을 보냅니다.
3. 첫 작업은 기본 배정으로 맡길 수 있습니다. 코디네이터가 작업 난이도를 판단하면 보드는 이 호스트의 로컬 프로필 Selector(`paseo/profile_selector.py`)에 모델을 묻습니다. 등급은 A=deep·xhigh, B=deep·high, C=work·high, D=work·medium, M=deep·high 역할·강도로 전달되며, Selector가 4개 한도 풀(직접 Claude·Codex·AGY Gemini·AGY 3P)의 남은 사용량을 고르게 나눠 고릅니다. Selector를 찾지 못하거나 결정을 보류하면 해당 등급은 보류 사유와 함께 배정되지 않습니다. 직접 정하고 싶을 때 보드 상단 **설정 → 모델 배정**을 엽니다. A(최상)부터 D(기본)까지 작업 난이도별로 우선 모델만 지정하거나 예비 후보와 추론 강도까지 저장할 수 있습니다. 예를 들어 C급은 Cursor의 Gemini를 먼저 쓰게 할 수 있습니다. **Selector로 복원**하면 그 등급은 다시 로컬 Selector를 따릅니다. 필수 훅을 요구하는 일은 Claude Code·Codex에 맡깁니다. 실제 모델 사용료는 내 계정의 구독·과금 조건을 따릅니다.
4. M은 코디네이터 자체를 생성하거나 교체할 때 사용할 모델입니다. M 후보를 바꿔 저장해도 현재 세션은 계속 일합니다. 담당자를 바꾸려면 **설정**에서 **새 코디네이터로 교체…**를 열고 **새 세션으로 교체**를 누릅니다. 새 세션을 확인한 뒤 담당자를 전환하며, 카드의 질문과 판단·기존 작업자는 이어집니다.

긴 요청은 **입력창 펼치기**로 넓게 읽고 수정하세요. 접었다 다시 펼쳐도 작성한 문구와 첨부한 사진이 유지됩니다.

**사진 첨부** · 데스크톱·웹의 작업 요청란과 **내 결정** 답변란에 사진을 끌어 놓거나 붙여 넣으세요. 클립 아이콘 **첨부 파일 추가**로도 선택할 수 있습니다. 미리보기에서 확인한 뒤 보내세요. PNG, JPEG, WebP를 최대 4장까지 지원합니다(장당 5 MiB, 합계 12 MiB). 사진만 보내도 됩니다. 모바일 네이티브 앱에서는 해당 세션의 대화 입력창에서 첨부할 수 있습니다. 사진을 읽지 못하면 파일을 다시 선택하거나 실패한 첨부를 취소한 뒤 보낼 수 있습니다. 이 버전부터 사진을 첨부해 보낸 요청·답장·질문은 받은 세션에서 본문과 사진을 함께 볼 수 있습니다. 사진을 누르면 크게 볼 수 있습니다. 플러그인은 호스트에 최근 사진 메시지 20건의 원본을 보관합니다.

**결정에 답할 때** · 담당 세션이나 코디네이터가 받는 메시지에는 프로젝트, 원래 질문의 세션·카드·질문 ID와 판본, 질문 문구가 함께 들어갑니다. 예전 카드의 ‘Q3’에 답해도 어느 질문인지 수신자가 확인할 수 있습니다. 원래 세션 ID가 없는 예전 기록은 출처 원장과 카드 ID로 식별합니다. 수신자가 없는 카드의 답과 사진은 보드에 보관할 수 있습니다.

직접 확인한 항목은 **확인했어요**에 체크하면 기록으로 옮깁니다. 다이제스트를 요청하면 지정한 코디네이터는 단독 병합 안건의 GitHub 병합 상태와 담당 세션에서 확인한 완료 근거를 바탕으로 확인 기록을 정리할 수 있습니다. 후속 질문이나 사람의 선택이 남은 카드는 열려 있습니다.

**계정별 남은 사용량** · 설정에서 현재 호스트가 알려 주는 기간별 잔여율과 초기화 시각을 확인합니다. 저장한 모델 순서가 없는 등급은 로컬 Selector가 공유 한도 기록(`quota-state.json`)으로 고르며, 코디네이터가 배정을 계획할 때 보드가 기록을 한 번 갱신합니다. 직접 저장한 모델 순서가 우선이며, 보고되지 않은 계정의 잔여량은 미확인으로 표시합니다.

계정 카드의 막대는 **남은 비율**입니다. 총한도가 없는 크레딧은 잔액만 표시합니다. 이전 측정에는 조회 시각을 붙이며, 초기화 시각을 지난 값은 다음 조회까지 숨깁니다.

Paseo가 잔여 수치를 제공하지 않는 실행기는 호스트 관리자가 플러그인 데이터 폴더(`$PASEO_HOME/plugin-data/coordinator-board`, 기본 `~/.paseo/plugin-data/coordinator-board`)에 `account-usage.json`을 제공할 수 있습니다. 파일은 설정을 열거나 **실행기·모델 새로 고침**을 누를 때 읽습니다. `providerId`에는 실행기 ID, `fetchedAt`에는 원래 측정 시각을 씁니다. 다음은 형식 예시입니다.

```json
{"version":1,"reports":[{"providerId":"studio-runner","label":"Studio · 편집 계정","plan":null,"status":"available","fetchedAt":"2026-11-22T10:00:00Z","windows":[{"id":"weekly","label":"주간","remainingPct":72,"resetsAt":"2026-11-28T10:00:00Z","summary":true}],"balances":[]}]}
```

호스트 추가 보고는 설정에 표시하는 용도입니다. 자동 배정은 Paseo의 사용량 보고서를 사용합니다. 실행기가 같은 구독을 공유할 때도 계정별 비율을 합산하지 않습니다.

처음 만든 운영 워크스페이스는 이 호스트의 Paseo 사이드바에 자동으로 고정됩니다. **설정 → 사이드바 고정**에서 자동 고정을 끌 수 있습니다. 같은 워크스페이스에서 세션을 교체하면 사용자가 정한 고정 상태가 유지됩니다. 이미 쓰던 코디네이터를 고정하려면 **현재 운영 워크스페이스 고정**을 누르세요.

처음 만들거나 교체할 코디네이터의 도구 권한은 버튼 위에서 확인합니다. 보드는 이 호스트가 제공하는 모드를 조회해 **Claude Code는 Auto mode**, **Codex는 Auto-review**를 우선 선택합니다. 우선 모드를 사용할 수 없으면 이 실행기가 제공하는 대체 권한 모드를 조회해 표시합니다. 이 두 실행기를 사용할 수 없으면 호스트에서 일반 작업 모드가 확인된 OpenCode(Build)나 Copilot(Agent)도 후보가 됩니다. 지원되는 모드를 확인할 수 없을 때는 실행기·모델을 새로 고치거나 Paseo MCP를 사용하는 기존 세션을 지정하세요. 다이제스트 요청은 지정된 코디네이터에 최신 질문과 결과를 정리하도록 요청합니다. 사실 질문 자동 답장이 켜져 있으면 코디네이터가 확인된 사실을 담당 세션에 전달할 수 있습니다. 자동 심사가 사람에게 돌려준 권한은 원래 세션에서 응답합니다. 새 작업 세션의 권한은 **설정 → Paseo 실행기 → 새 작업 세션 권한**에서 고릅니다. 배정할 때 해당 실행기가 선택한 모드를 지원하는지 확인합니다. 이미 사용하는 세션의 모드는 Paseo의 세션 권한 메뉴에서 바꿀 수 있습니다.

작업 세션은 보드를 연 호스트에 생성됩니다. 코디네이터는 관리 프로젝트 안의 작업 위치에 새 세션을 만들 수 있습니다. 외부 프로젝트에서 연결한 세션은 지정된 그 세션만 관리 범위에 들어옵니다. 작업 요청·카드 답장·질문·다이제스트 전송과 작업자 실행에는 수신 세션의 모델 사용 조건이 적용됩니다. 보드 조회와 배정표 편집은 호스트의 목록과 설정을 사용합니다.

## Paseo에 연결한 실행기 사용하기

**설정 → Paseo 실행기**를 열면 보드가 현재 호스트의 Paseo에 실행기와 모델을 묻습니다. 새로 연결한 실행기는 기본으로 배정 후보에 포함됩니다. 설정을 열어 둔 채 다른 도구를 연결했다면 **실행기·모델 새로 고침**을 누르세요. 각 항목에서 Paseo에 등록한 이름과 ID, 선택 가능한 모델 수, 배정할 수 있는 작업 등급을 확인할 수 있습니다. 모델이 없는 경우와 모델 목록을 읽지 못한 경우도 구분해 표시합니다.

예를 들어 코디네이터가 Codex여도 C급 작업자는 Cursor의 Gemini나 이 호스트에 등록된 다른 ACP 실행기로 지정할 수 있습니다. **모델 배정**에서 등급을 고른 뒤 실행기별 필터로 모델을 둘러보거나 실행기·모델 이름과 ID를 검색하세요. 같은 모델 ID를 제공하는 두 실행기는 서로 다른 후보입니다. 선택한 등급에서 실제로 적용할 모델은 목록 맨 앞에 표시되며, Selector 또는 저장한 배정의 추론 강도까지 선택됩니다. Selector가 고른 이유나 보류 사유도 함께 표시됩니다. 모델이 전혀 없으면 연결하거나 다시 포함할 실행기를 안내합니다. 저장한 우선순위가 있으면 사용 가능한 첫 후보를 씁니다. 저장한 후보를 모두 사용할 수 없을 때는 후보를 바꾸거나 **Selector로 복원**하세요.

특정 도구를 쉬게 하려면 해당 항목의 **배정에 포함됨**을 눌러 제외하세요. 이후 배정은 포함된 후보 중에서만 고릅니다. 저장해 둔 후보의 순서는 유지되므로 다시 포함하면 같은 우선순위를 사용할 수 있습니다. 칸반 카드는 기존 세션이 실제로 사용하는 실행기와 모델을 보여 줍니다.

## 다른 기기의 세션 찾아보기

**설정 → Paseo 호스트**에는 앱에 등록한 기기가 모두 표시됩니다. 새로 등록한 기기도 기본으로 포함합니다. 이름 아래에서 **세션 목록에 표시 중** 또는 **세션 목록에서 숨김**을 확인하고, 옆의 **숨기기** 또는 **표시하기**를 눌러 바꿉니다. 오프라인 기기는 연결 상태를 표시하고, 다시 연결되면 목록을 열 수 있습니다. 같은 설정 안의 **기기별 세션 찾아보기**에서 기기를 고르면 그때 해당 호스트에 세션 목록을 요청합니다. 이름이 같은 기기는 식별자를 확인하세요. 목록에서 제외한 기기는 보드를 다시 열어도 숨겨집니다. 이 설정은 호스트별 세션 목록에 적용됩니다. 작업 배정과 다이제스트는 코디네이터가 있는 호스트에서 진행됩니다. 다른 기기의 세션을 표시해도 새 작업자가 생성될 기기는 바뀌지 않습니다. 예를 들어 Windows 작업을 배정하려면 Windows 호스트의 보드에서 요청하세요.

### GitHub PR과 내 결정

사이드바와 **내 결정**은 관리 프로젝트의 세션 질문, 병합 검토 PR, 연결된 결정 원장을 함께 셉니다. 원장에서 같은 PR이나 같은 세션 질문을 확인하면 한 카드에 표시합니다. 관리 프로젝트에 GitHub 원격 저장소가 있으면 호스트의 GitHub CLI(`gh`)로 열린 PR을 조회합니다. 병합 조건을 충족한 PR은 **내 결정**에 뜹니다. **보드에서 병합**을 눌러 저장소, 대상 브랜치, 검토할 커밋과 사용할 병합 방식을 확인하세요. **병합 확정**을 누르면 호스트에 로그인한 GitHub 계정으로 요청을 보냅니다. 새 커밋이 올라왔거나 병합 조건이 바뀌면 다시 검토해야 합니다. 변경 내용을 읽으려면 카드 위의 **저장소 이름과 PR 번호**를 누르세요. GitHub에서 해당 PR이 열립니다. 초안이나 검사 중인 PR은 **프로젝트별 진행**에서 볼 수 있습니다. 여러 프로젝트가 같은 저장소를 쓰면 내 결정에서는 PR 한 건으로 셉니다.

GitHub가 보드에서 요청한 병합을 확인하면, 보드는 담당 코디네이터 세션에 PR 링크와 확인된 병합 커밋을 전달합니다. 코디네이터는 이 알림으로 후속 작업을 판단하므로 모델 사용량이 발생할 수 있습니다. 세션이 바쁘면 대기열에 두고, 카드와 **최근 결정 기록**에서 전달 상태를 확인할 수 있습니다. 다른 곳에서 이미 병합한 PR을 조회할 때는 알림을 보내지 않습니다.

저장소를 자동으로 찾지 못했거나 다른 저장소를 보고 싶다면 **설정 → 프로젝트별 GitHub 저장소**에서 `owner/repository`를 입력하세요. **PR 조회 끄기**로 프로젝트별 조회를 끌 수 있습니다. 조회에 실패하면 보드를 연 호스트에서 `gh`의 설치와 저장소 접근 권한을 확인하세요.

## 내 환경에 맞게 고치기

ZIP에는 TypeScript 원본이 들어 있습니다. 기본 모델과 추론 강도는 보드에서 바꾸고, 기본 후보 선정 방식을 바꾸려면 `shared/dispatch.ts`를 확인하세요. 코디네이터에게 자동 적용되는 헌장은 `server/lifecycle.ts`, 배정 가능한 작업 공간을 조회하고 작업자에게 맡기는 도구는 `server/operations.ts`에 있습니다. 기존 세션에 자기 기준을 설명할 때는 [운영 예시](templates/coordinator-session.md)에서 공개·예산 변경처럼 직접 답할 일을 골라 적을 수 있습니다. 수정한 사본은 시험 호스트에서 다시 불러와 확인하세요.

### 결정 카드에서 답하거나 조율 요청하기

원장 카드 위의 **운영 코디네이터**를 누르면 그 원장을 관리하는 세션이 열립니다. **원래 작업 세션**이 따로 있으면 두 칩 중에서 고를 수 있습니다. 프로젝트별 진행에서 카드를 접어 두어도 칩을 누를 수 있습니다. 답장을 받을 세션은 전송 버튼에서 확인하세요.

운영 코디네이터가 Claude 또는 Codex로 작업 중이어도 여러 카드에 연이어 답할 수 있습니다. 각 답장은 해당 카드와 질문 ID를 유지합니다. 권한 확인 중이거나 담당 작업 세션이 바쁘면 원장 카드에 **전송 대기**가 표시됩니다. 보드를 닫아도 예약은 유지되며, 받는 세션이 준비되면 원래 질문과 수신자를 다시 확인하고 전송합니다. 전송 전에는 카드에서 취소할 수 있습니다.

카드 위 **담당 세션** 칩을 누르면 원래 대화가 열립니다. PR 번호는 GitHub 변경 내용을 엽니다. PR과 일치하는 작업공간이 있으면 세션 이름·호스트·상태를 표시하는 칩이 함께 뜹니다. **작업 세션 미확인**은 현재 조회 범위에서 연결을 확인할 수 없다는 뜻입니다.

보드 제목 아래에서 보고 싶은 프로젝트를 모두 누르세요. **내 결정**, **최근 결정 기록**, **프로젝트별 진행**에 선택한 프로젝트가 함께 표시됩니다. 프로젝트 옆 숫자는 지금 결정할 건수입니다. 두 프로젝트가 공유하는 PR은 내 결정에서 한 번만 셉니다. 선택한 이름을 다시 누르면 그 프로젝트가 빠지고 **전체**를 누르면 모든 프로젝트가 보입니다.

병합과 후속 작업을 함께 묻는 카드에서는 PR 번호를 눌러 GitHub로 이동할 수 있습니다. 이미 병합된 PR에는 **병합 완료**가 표시됩니다. 아래에 남은 질문의 선택지를 고르면 해당 질문에 대한 답만 전송합니다.

**내 결정**에서 먼저 결정할 질문 한 줄과 추천 답장을 읽으세요. 각 결정은 카드 하나에 표시됩니다. 추천 답장은 입력란에 미리 채워지며 그대로 수정할 수 있습니다. 긴 답장은 **답장 전문 보기**로 펼쳐 확인하세요. 입력란 아래에서 받는 세션 이름이 적힌 전송 버튼을 누르면 그 내용이 전달됩니다. 선택지가 있으면 카드에서 바로 고르고, 추천 답장이 없으면 입력란에 직접 답을 써서 보낼 수 있습니다. 예전에 만든 카드에서 **코디네이터에 추천 요청**을 누르면 그 질문 하나의 근거를 다시 검토합니다. 조율은 **다른 방법**, 원문과 추천 이유는 **근거 보기**에서 확인할 수 있습니다.

설명이 더 필요하면 그 카드의 **질문하기**를 누르세요. 예를 들어 “네 곳 중 어디를 먼저 확인하면 되나요?”라고 쓰고, 수신 세션을 확인한 뒤 **질문 보내기**를 누릅니다. 사진도 첨부할 수 있습니다. 보낸 질문과 돌아온 설명은 같은 카드의 **문답**에 이어집니다. 원래 질문은 계속 **내 결정**에 남아 있어 설명을 읽고 답할 수 있습니다.

예를 들어 작업자가 “이 세션의 원래 프로젝트가 어디인가요?”라고 묻는다면 보드가 확인할 수 있는 사실입니다. **다이제스트 요청**을 누르면 지정된 코디네이터가 해당 세션에 프로젝트 정보를 보내고, **프로젝트별 진행**에 처리 기록을 남깁니다. 자동 답장은 호스트마다 기본으로 켜져 있으며 **설정 → 사실 질문 자동 답장**에서 끌 수 있습니다. 답장을 받은 세션이 모델을 실행하면 해당 제공자의 사용량에 반영될 수 있습니다. “작업 폴더를 지울까요?”처럼 사람의 판단이나 권한이 필요한 질문은 **내 결정**에서 검토합니다.

| 하려는 일 | 카드에서 누를 항목 | 받는 곳 |
|---|---|---|
| 추천대로 답하거나 선택지 고르기 | 입력란의 문장을 확인한 뒤 **담당 세션에 답장 보내기** | 담당 작업 세션 |
| 내용을 고쳐 답하거나 직접 쓰기 | 입력란에서 수정 → 수신자가 표시된 전송 버튼 | 담당 작업 세션 |
| 결정 전에 한 가지 더 묻기 | **질문하기** → **질문 보내기** | 카드에 표시된 작업 세션 또는 코디네이터 |
| 다른 일과 우선순위·역할 조율하기 | **코디네이터에 조율 요청** → **코디네이터에 조율 요청 보내기** | 지정된 코디네이터 세션 |
| Paseo의 도구 권한·플랜 승인 요청 처리하기 | **담당 세션 열기** → Paseo의 승인 화면에서 응답 | 요청이 열린 원래 세션 |

보내기 전에 **받는 곳**과 문장을 확인하세요. 현재 세션의 대화 근거와 카드 상태가 바뀌면 보드를 새로 고친 뒤 응답합니다. 직접 보낸 답장은 결과를 기다리는 **확인 대기**에 반영됩니다. 추가 질문을 보낸 카드는 문답을 확인한 뒤 결정할 수 있습니다. 결과를 확인한 다음 **기록 추가** 또는 **기록 편집**에서 완료 근거를 남기세요.

## 대화에서 사람 차례를 찾는 방법

보드는 선택한 프로젝트 안에서 응답이 끝난 세션의 최근 타임라인을 읽습니다. 최대 48개 항목에서 사용자·에이전트의 최근 대화 4개만 발췌하며, 발화마다 마지막 2,000자까지 사용합니다. 기본 분류는 “확인해 주실 것”, “어느 쪽으로 할까요?” 같은 한국어·영어 표현을 살펴보고 질문과 선택지를 표시합니다. 변화가 없는 발췌는 짧게 재사용합니다. 닫힌 세션은 보드가 다시 띄우지 않습니다.

기존 세션을 쓸 때는 **설정 → 기존 세션에서 코디네이터 지정**으로 들어가 관리 중인 세션을 고릅니다. 다음 대화용 실행 때 Paseo MCP가 연결된 코디네이터에 `read_board_conversation`과 `classify_board_conversation`이 붙습니다. 첫 도구는 관리 세션 목록이나 해당 세션의 최근 발췌를 읽고, 둘째 도구는 현재 발췌 ID에 질문·검토·대기 판단을 기록합니다. 새 작업을 위임받으면 `plan_board_assignment`로 관리 프로젝트, 세션, 워크스페이스와 모델 후보를 확인하고 `assign_board_worker`로 작업자를 생성합니다. 이미 열려 있는 세션이라면 턴이 끝난 뒤 해당 세션만 다시 불러오세요. 시험 호스트에서는 `paseo agent reload <세션 ID>` 후 코디네이터 도구가 나타났습니다. 코디네이터에게 [첫 요청](templates/coordinator-session.md)을 보내면 관리 세션을 살피고, 발췌와 기존 지시를 대조해 질문·확인 대기·대기로 분류할 수 있습니다. 검토·대기 판단은 기록한 발췌에 적용됩니다. 후속 발화가 이어져도 코디네이터가 기록한 열린 질문과 필요한 입력은 **내 결정**에 남습니다. 세션의 최신 발화에서 감지한 또 다른 질문은 카드의 **근거 보기**에서 확인할 수 있습니다. 코디네이터가 별개 질문으로 확인해 등록하면 그 질문에 답할 수 있고, 앞서 등록한 미해결 질문도 보존됩니다. 이미 보드에 적은 사람의 질문은 기록 편집에서 직접 정리할 수 있습니다. 보드를 여는 동작 자체가 코디네이터를 실행하지는 않습니다.

## 내 세션에서 질문을 올리기

보드 조회와 직접 기록은 설치 직후 사용할 수 있습니다. 세션의 자동 보고에는 Paseo MCP를 지원하는 실행기와 호스트의 도구 연결이 필요합니다. Paseo 0.16.2의 설정 이름은 `daemon.mcp.enabled`와 `daemon.mcp.injectIntoAgents`입니다. 뒤의 설정은 호스트의 에이전트에 제공하는 Paseo 도구 전반에 적용됩니다. 제공 범위를 확인하고 사용 여부를 선택하세요. [Paseo MCP 설정](https://paseo.sh/docs/mcp)

1. 보고받을 세션 카드의 **기록 추가** 또는 **기록 편집**에서 **보드 보고 켜기**를 누릅니다.
2. 그 세션이 다음에 대화용으로 열리면 지원하는 실행기에 `report_to_board` 도구가 제공됩니다. 이미 실행 중인 턴은 그대로 진행됩니다. 선택한 코디네이터 세션에는 [설계·운영 시작 문장](templates/coordinator-session.md)을 자기 기준에 맞춰 붙여 넣을 수 있습니다.
3. 그 세션이 질문을 올리면 **내 결정**, 확인할 결과를 올리면 카드에 **세션 보고**가 표시됩니다. 도구는 자기 카드에만 쓸 수 있습니다. 사용자가 남긴 기록은 사용자가 직접 편집하거나 해제합니다.

## 로컬 데이터와 제거

보드는 선택한 호스트에서 Paseo SDK로 세션·워크스페이스 목록을 조회합니다. 보드 조회는 모델을 호출하지 않습니다. 보고를 켠 세션의 실행기가 모델을 사용할 때는 해당 제공자 설정이 적용됩니다. 선택한 프로젝트의 대화 발췌는 호스트 메모리에 잠시 유지됩니다. 지정한 코디네이터가 발췌 도구를 호출할 때는 해당 모델의 대화 맥락으로 전달됩니다. 관리 범위, 세션 연결, 코디네이터의 판단 요약, 중복 전송 확인용 영수증은 호스트의 Paseo 홈 아래 `plugin-data/coordinator-board/scope.json`에 저장됩니다. 직접 적은 질문과 근거는 그 호스트의 Paseo 홈 아래 `plugin-data/coordinator-board/notes.json`에 저장합니다. 설치 디렉터리와 분리되어 업데이트 뒤에도 보존됩니다.

질문과 근거 원문은 로컬 JSON에 평문으로 보관됩니다. 설치한 호스트에서 `paseo plugin ls coordinator-board`로 상태를 확인합니다. 잠시 끄려면 `paseo plugin disable coordinator-board`, 다시 켜려면 `paseo plugin enable coordinator-board`를 실행합니다. 설치 등록을 지우려면 `paseo plugin remove coordinator-board`를 실행하고 `paseo plugin ls`에서 목록을 확인합니다. 다른 호스트를 대상으로 할 때는 각 명령 끝에 `--host 호스트주소:포트`를 붙이세요. 디렉터리 설치의 원본 폴더는 별도로 보관됩니다. 직접 남긴 기록까지 지우려면 해당 호스트에서 보관할 기록을 먼저 확인하세요. 이 패키지는 MIT 라이선스로 배포합니다. ## 프로젝트별 칸반과 결정 원장

칸반에는 작업이 있는 상태가 함께 표시됩니다. 데스크톱에서는 열을 나란히 보고, 휴대폰에서는 상태별로 아래로 읽을 수 있습니다. 각 세션에 실행 호스트가 표시됩니다. 설정에서 표시하도록 선택한 다른 호스트도 연결되어 있고 프로젝트 소속을 확인할 수 있으면 **다른 호스트에서 진행 중**에 나타납니다. 세션 열기는 해당 호스트의 대화로 이동합니다.

프로젝트 운영자는 플러그인 데이터 폴더의 `tracked-decisions.json`에 독립적인 결정을 제공할 수 있습니다. 같은 세션에서 여러 작업을 맡거나, 실기 확인과 병합을 따로 추적할 때 사용하세요. 다음은 항목 한 개 예시입니다. `projectId`에는 보드에서 관리하는 Paseo 프로젝트의 실제 ID를 사용합니다.

```json
{"version":1,"items":[{"source":"studio","projectId":"YOUR_PROJECT_ID","id":"playback","kind":"check","title":"모바일 재생 확인","where":"human","steps":["휴대폰에서 영상을 재생하고 첫 자막을 확인하세요."]}]}
```

결정에 마감이 있으면 `dueAt`에 날짜 또는 시간대가 포함된 시각을 적으세요. `since`는 결정을 기다리기 시작한 시각입니다. 배포처럼 다음 단계가 이 결정에서 실제로 멈췄다면 `blocksWork: true`를 지정하세요. 병합 준비가 끝난 PR에 후속 작업이 있다는 근거가 없으면 일반 검토 순서를 따릅니다.

기존 프로젝트별 JSON 원장을 운영하는 호스트는 같은 폴더에 `tracked-sources.json`을 둘 수 있습니다. `version`은 1이고 `sources` 각 항목에 `source`, `projectId`, `projectTitle`, `directory`를 지정합니다. `directory`는 `decisions.json`이 있는 디렉터리의 절대 경로입니다. `repository`에 GitHub 저장소를 지정하면 병합 항목을 같은 PR과 연결합니다. `coordinatorFile`에는 원장을 맡은 현재 세션의 `agentId`를 담은 JSON 파일의 절대 경로를 지정합니다. 보드는 답장을 보낼 때도 소유자를 다시 확인합니다. 운영 세션을 확인할 수 없는 카드는 로컬에 답을 기록할 수 있습니다. **내 결정**에서 A/B 선택지와 추천 표시, 직접 답변란을 확인하세요. 선택한 답을 확인한 뒤 수신자가 표시된 전송 버튼을 누르세요. **보드에만 저장**는 현재 판본의 답을 보드에 보관합니다. 근거와 이전 문답은 펼쳐서 볼 수 있습니다. PR 병합은 별도로 확정합니다.
