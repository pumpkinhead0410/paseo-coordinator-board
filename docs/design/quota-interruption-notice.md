# 사용량 한도 중단 알림의 전달 범위

Paseo 0.17.4에서 실제 작업자 `d5dcb57e-988c-80a2-8581-f26835807962`의 공개 타임라인 끝을 조회했습니다. Antigravity는 `Individual quota reached`를 마지막 assistant 메시지로 기록했습니다. 메시지 시각은 2026-11-27 10:36:04 KST, 제공자가 표시한 남은 시간은 2h49m33s로, 계산한 회복 예상 시각은 13:25:37 KST입니다. 직전 완료 도구는 `shared/contract.ts` 읽기였습니다. 이 발췌에서 커밋은 확인되지 않았습니다.

보드 화면과 해당 호스트의 사이드바 항목이 수신기입니다. 마운트 직후와 이후 30초마다 현재 관리 세션을 조회하고, 권한 대기나 활성 턴이 없고 보드에서 미완료인 세션의 마지막 타임라인 항목을 확인합니다. 오인 비용을 줄이기 위해 Antigravity의 정형 경고와 명시적인 한도 오류만 인식합니다. 인계 후보는 같은 관리 프로젝트에서 다른 제공자로 대기 중인 세션으로 제한합니다. 계정 잔여량이나 수임 승인은 별도로 확인해야 합니다.

## 수신 경로 시험

운영 플러그인 교체 없이 React 19.1 테스트 렌더러로 등록된 화면과 사이드바 컴포넌트를 마운트했습니다. 실제 사건의 타임라인 항목을 재생하고 등록된 서버 RPC와 임시 디스크 설정 원장을 연결했습니다. 토스트 서비스의 `show` 호출을 계수했습니다.

| 마운트 및 입력 | 토스트 호출 |
|---|---:|
| 보드 없이 사이드바만 마운트, 첫 중단 | 1 |
| 플러그인 서버 재생성 후 보드 마운트, 같은 중단 | 0 |
| 현재 화면이 보드일 때 사이드바 마운트, 새 턴의 동일 경고 | 0 |
| 같은 새 턴에 보드 화면 마운트 | 1 |

`bun test test/quota-notice.test.ts`는 동시 조회, 디스크 원장 재사용, 타임라인 재투영, 실제 새 턴, 프로젝트 연결·해제, 조회 중 재개, 사용자 인용, 완료·권한 대기 등의 조건을 검사합니다.

두 수신기가 모두 내려가면 앱 내부 토스트를 호출할 수 없습니다. 다시 열 때까지 마지막 항목이 유지된 중단은 회수할 수 있습니다. 앱 종료 중 OS 푸시와 다중 기기의 실제 화면 표시는 검증 범위 밖입니다. 호스트별 원장은 동일 사건을 한 클라이언트가 선점하게 하며, 선점 직후 연결이 끊기면 사람이 읽기 전에도 중복 억제가 적용됩니다. SDK의 토스트 API는 표시·열람 영수증을 제공하지 않습니다. 앱 종료 중 전달이 필요하면 별도의 수신 채널과 배달 확인 계약을 정해야 합니다.
